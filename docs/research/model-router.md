# Исследование: роутер моделей для генератора татуировок

- **Статус:** отдельный инженерный трек назначен владельцем; это задание
  на исследование, а не его результат и не выбор библиотеки.
- **Дата:** 2026-09-09.
- **Связи:** [размещение](../adr/0004-yandex-cloud-and-generation-harness.md),
  [попытки](../adr/0006-generation-attempts-and-usage.md),
  [файлы и удаление](../adr/0007-sketch-storage-uploads-and-deletion.md).

## Инженерная задача

Роутер выбирает сервис и модель для задания, переводит запрос в нужный API
и возвращает харнессу понятный результат. Рассматриваем Yandex AI Studio
и NanoGPT. Сам роутер работает в Yandex Cloud; правила передачи данных
сервисам должны быть частью его контракта.

Генератор выделен в самостоятельный внутренний сервис по
[ADR-0008](../adr/0008-independent-generation-service.md). Это не определяет,
будет ли роутер библиотекой внутри генератора или отдельным сервисом.

Сравнить LiteLLM и собственный небольшой роутер. Для LiteLLM отдельно оценить
использование Python SDK внутри программы и отдельного Proxy Server.
На вводной странице LiteLLM документированы оба варианта, общий интерфейс
для API моделей, повторные запросы, переключение между сервисами и учёт
использования. Это пока не подтверждает совместимость с нужными нам
маршрутами изображений Яндекса и NanoGPT.

## Что исследовать

| Область | Вопрос исследования |
| --- | --- |
| Подготовка задания | Текстовые запросы, режимы рассуждений, структурированный результат и ограничения модели |
| Создание изображения | Поддержка конкретных API, параметры, форматы результата, ожидание и ошибки |
| Правки | Входной оригинал, пользовательская загрузка, сохранение композиции, поддержка маски при наличии |
| Выбор маршрута | Соответствие возможностей модели операции, доступность, качество, задержка и стоимость |
| Сбои | Ограничения частоты, таймаут, неизвестный исход, идентификатор внешней операции, возможность проверки результата |
| Повторы | Какие ошибки допускают повтор или другой сервис без риска скрытого двойного вызова |
| Данные | Что уходит в каждый сервис, где обрабатывается и сохраняется, как отключается логирование и удаляются копии |
| Учёт | Отделение попытки клиента от вызовов моделей; расчётная и фактическая стоимость |
| Эксплуатация | Зависимости, версии, лицензия выбранного варианта, обновления, хранение настроек и диагностика |

Проверить отдельно создание по тексту и работу с изображением. Совместимость
с одним текстовым API не доказывает совместимость всех методов.
Не добавлять автоматическое переключение в другой сервис при неизвестном
исходе оплачиваемого запроса. Маршрут не должен обходить правила доступа
к загруженному файлу, его удаление или выбранные ограничения передачи данных.

## Результат трека

- Матрица подтверждённых возможностей по версиям библиотек, API и моделей.
- Сравнение LiteLLM SDK, LiteLLM Proxy и собственного роутера на наших операциях.
- Предложенный интерфейс между кабинетом, харнессом и роутером.
- Правила ошибок, повторов, выбора сервиса и учёта расходов.
- Проверочные задания для эскизов и последовательных правок с оценкой мастером.
- Рекомендация с обоснованием и отдельный ADR о выбранном решении.

Платные прогоны и подключение ключей требуют согласованной программы проверки;
в этом треке они пока не выполнены. Продукт продолжаем проектировать параллельно.
