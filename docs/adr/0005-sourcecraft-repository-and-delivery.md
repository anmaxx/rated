# ADR-0005: SourceCraft для репозитория и публикации

- **Статус:** принят выбор SourceCraft; детали перехода и публикации уточняются.
- **Дата:** 2026-09-09.
- **Принимает решение:** владелец проекта.
- **Связь:** [Yandex Cloud и генерация](0004-yandex-cloud-and-generation-harness.md).
- **Состояние реализации:** репозиторий остаётся на GitHub. Импорт, настройку
  SourceCraft, изменение адресов Git и публикации сайта не выполняли.

## Задача и текущее состояние

Владелец предложил рассмотреть SourceCraft, чтобы хранение кода, ревью,
сборка и публикация проекта были связаны с выбранным Yandex Cloud.
CI/CD здесь означает автоматические проверки, сборку и публикацию изменений.
После рассмотрения владелец принял SourceCraft как основную площадку.
Принятое решение ещё не исполнено: организация, видимость и доступ
к целевому репозиторию не настроены.

Локальная проверка 2026-09-09:

- `origin` указывает на `git@github.com:anmaxx/rated.git`.
- Текущая ветка `feat/contacts-map`, HEAD `113593d`.
- `.github/workflows/static.yml` собирает Vite на Node.js 22 командами
  `npm ci` и `npm run build`, затем публикует `dist/` в GitHub Pages.
- Публикация запускается после изменений `master` или вручную; работает
  последовательно, без отмены уже выполняющегося выпуска.
- В HEAD 169 файлов общим размером около 15 МиБ. Локальные Git-объекты занимают
  около 143 МиБ; эта оценка не является размером полного импорта GitHub.
- Черновики `docs/adr/` пока не отслеживаются Git. Импорт удалённого репозитория
  не перенесёт их автоматически.

SourceCraft будет хранить исходный код и сведения о разработке. Клиентские
анкеты, эскизы и база приложения остаются в предназначенных для них сервисах
Yandex Cloud по ADR-0004. Перенос репозитория сам по себе не меняет размещение
работающего сайта и способ приёма форм.

## Что можно перенести и что нужно настроить

Проверено по официальной документации SourceCraft 2026-09-09:

| Часть | Возможность | Работа для Rated |
| --- | --- | --- |
| Git | Импорт истории коммитов, веток и тегов | Сверить выбранные ветки, теги и идентификаторы коммитов после переноса |
| Обсуждения | Из GitHub опционально импортируются предложения изменений, задачи и комментарии | Выбрать полный импорт и проверить сохранность нужных обсуждений; номера и ссылки не считать неизменными |
| Ревью и защита веток | Правила в `.sourcecraft/review.yaml` и `.sourcecraft/branches.yaml` | Восстановить запрет прямого push и переписывания основной ветки; сохранить слияние владельцем и проверить обязательные одобрения |
| Сборка | Собственная конфигурация `.sourcecraft/ci.yaml`; доступны события push и pull request | Перенести команды сборки и добавить проверку предложений изменений без права публикации |
| Доступ к Yandex Cloud | Сервисное подключение выдаёт краткоживущий IAM-токен для задания | Настроить доступ только к ресурсам публикации и только из разрешённой ветки |
| Рабочие инструменты | Git, SourceCraft CLI и публичный REST API | Git-команды сохраняются; действия через `gh` и инструкции для GitHub требуют замены |

Импорт обсуждений происходит при первой синхронизации и не является постоянной
синхронизацией между двумя площадками. Настройки GitHub, секреты, права,
проверки слияния и историю запусков Actions не считаем перенесёнными без
отдельного подтверждения. Для импорта сущностей GitHub помимо кода документация
требует токен администратора репозитория; настройка доступа относится к будущему
переносу, токены в этой оценке не запрашивались.

SourceCraft умеет выполнять отдельные GitHub Actions внутри собственного
сценария на облачных исполнителях. Это не означает автоматический запуск
нашего `.github/workflows/static.yml` или перенос GitHub Pages. Для текущей
простой сборки предлагаем обычные команды в `.sourcecraft/ci.yaml`, с версией
Node.js, удовлетворяющей `package.json` и lockfile. Публикацию Pages заменяем.

## Варианты

| Вариант | Что упрощает | Что остаётся |
| --- | --- | --- |
| SourceCraft как основной репозиторий и CI/CD, приложение в Yandex Cloud | Код, ревью и доступ сборок к облаку связаны встроенными средствами | Разовая настройка новой публикации и правил работы; рекомендуемый вариант |
| GitHub для кода и CI/CD, публикация в Yandex Cloud | Меньше изменений в привычных инструментах | Две платформы и отдельная интеграция доступа к облаку |
| GitHub как основной, SourceCraft как зеркало | Позволяет ознакомиться с копией репозитория | Сохраняет две площадки; синхронизация обсуждений ограничена, не упрощает постоянную работу |

Выбран один основной репозиторий в SourceCraft после проверенного перехода.
Приватный репозиторий предлагается как исходный вариант для студии; видимость
не определена владельцем. SourceCraft и его CI/CD не заменяют сервер приложения:
запросы клиентов на генерацию выполняются харнессом из ADR-0004, а не заданиями
сборки репозитория.

## Публикация сайта и ограничения SourceCraft Sites

SourceCraft Sites предлагает статический хостинг из публичного репозитория
публичной организации, с HTTPS и адресом
`https://<организация>.sourcecraft.site/<репозиторий>`. Публикуются файлы
выбранной ветки или тега. Для Vite нужно отдельно подготовить результат сборки;
исходный `index.html` не заменяет собранный `dist/`.

В проверенных материалах не подтверждено подключение `ratedtattoo.ru`
к SourceCraft Sites. Это ограничение проведённой проверки, а не утверждение
о невозможности такой функции. Sites также не исполняет серверную часть
кабинета и генератора.

Для рабочего сайта предлагаем публикацию `dist/` из SourceCraft CI/CD
в Yandex Object Storage в России: собственный домен и HTTPS там документированы.
Хранилище публичной сборки отделяем от закрытых оригиналов и предпросмотров
клиентов. Certificate Manager и DNS настраиваем для сохранения `ratedtattoo.ru`.
Способ размещения сервера и харнесса остаётся решением ADR-0004.

## Стоимость и масштаб

На дату проверки SourceCraft Free допускается использовать независимо
от сферы деятельности. В нём указаны 2 ГБ хранилища для публичных и 2 ГБ
для приватных репозиториев организации, 1 000 минут CI в месяц для каждой
из этих категорий и до пяти параллельных CI-процессов. SourceCraft Pro стоит
250 рублей за активного пользователя в месяц с НДС. Code Assistant оплачивается
отдельно; для переноса он не требуется.

По локальной оценке объёма Rated можно рассматривать Free для старта,
если квота организации не занята другими проектами. Реальное время сборок
и квоты аккаунта пока не проверены. Хостинг сайта, сервер, хранилище данных
и вызовы моделей оплачиваются отдельно от тарифа репозитория.

Есть технические пределы: клонирование в CI должно завершиться за 60 секунд,
артефакты одного шага ограничены 100 МБ. При пробной сборке нужно проверить
получение нашей истории и размер готового `dist/`. Удалять историю ради
предполагаемого ограничения не предлагаем.

## Порядок перехода

При подготовке и выполнении принятого перехода:

1. Зафиксировать исходное состояние удалённого `master`, веток и тегов;
   сохранить локальные черновики согласованным способом. Не подменять
   удалённый `master` одноимённой локальной веткой без сверки.
2. Создать целевую организацию или выбрать существующую, импортировать Git
   и нужные обсуждения. Сверить коммиты, ветки, теги, выбранные обсуждения
   и доступ владельца. Получить рабочую копию из SourceCraft.
3. Подготовить нативную сборку и правила ревью. Проверка предложений изменений
   не должна получать права публикации; неуспешная сборка не публикует сайт.
   Проверить запрет прямого push, правила слияния и требуемый squash.
4. Настроить публикацию в тестовое окружение Yandex Cloud. Проверить сайт
   в браузере, файлы по абсолютным путям, видео, карту, формы и HTTPS.
   Если к этому этапу существует кабинет, проверить прямое открытие его URL
   и настройки доступа браузера к API.
5. Проверить последовательность выпусков: старая сборка не должна затереть
   более новую. Заранее сохранить предыдущий рабочий выпуск и проверить возврат
   к нему. Для загрузки статических файлов определить порядок обновления
   ресурсов и `index.html`, чтобы пользователи не получали смешанную сборку.
6. После приёмки переключить домен и рабочий процесс разработки. Убедиться,
   что опубликована нужная сборка. Исключить конкурирующую публикацию из GitHub
   и обратную перезапись веток зеркалом. Исходный репозиторий сохранить
   на период проверки, его дальнейший статус определить отдельно.
7. Обновить `CLAUDE.md`, инструкции публикации, ссылки на ревью и Git remote.

Это порядок будущего перехода, а не выполненные действия или готовый
конфигурационный файл. Перенос репозитория и переключение рабочего сайта
проверяются отдельно; завершение импорта не означает завершение миграции сайта.

## Открытые решения

- Организация, видимость репозитория и состав переносимых обсуждений.
- Способ публикации `ratedtattoo.ru` и настройки доменов сервера и кабинета.
- Правила слияния, успешных проверок и порядок публикации выпусков.
- Статус исходного GitHub-репозитория после приёмки перехода.
