# Архитектурные решения Rated Tattoo

В ADR (Architecture Decision Record) фиксируем существенное решение,
его причины, рассмотренные варианты и последствия для проекта.

## Отдельные инженерные треки

- [Исследование роутера моделей](../research/model-router.md): Yandex AI Studio
  и NanoGPT, LiteLLM или собственная реализация. Пока оформлено задание,
  результат исследования и выбранное решение отсутствуют.
- [Устройство сервера](../design/server-runtime.md): исполнение, база, сеансы,
  файлы, фоновые задачи, удаление и публикация. Генератор выделен в самостоятельный
  сервис по ADR-0008; стек пока не выбран.

## Порядок работы

- В черновике отделяем согласованные требования от предложений и открытых вопросов.
- Статус «Принят» ставим после явного решения владельца по документу.
  Согласие с отдельным сценарием учитываем в соответствующем разделе.
- В принятом ADR сохраняем историю решения. Если меняем решение, создаём новый ADR
  и связываем документы.
- План реализации и результаты проверок ведём отдельно. Принятый ADR сам по себе
  не означает, что функцию реализовали или опубликовали.

Решения по роутеру и устройству сервера выделяем в новые ADR после исследования
и обсуждения конкретных вариантов. Номера присваиваем последовательно.
