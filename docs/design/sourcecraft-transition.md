# Переход разработки Rated в SourceCraft

- **Статус:** конфигурация подготовлена, импорт ещё не выполнен.
- **Дата:** 2026-09-15.
- **Основание:** [ADR-0005](../adr/0005-sourcecraft-repository-and-delivery.md).
- **Назначение:** порядок первого импорта и проверяемые условия переключения разработки.

## Цель

Основной площадкой разработки становится приватный репозиторий `rated` в проекте
[`org-anmaxmoscow / Rated`](https://sourcecraft.dev/org-anmaxmoscow/projects/rated/repos).
Сайт продолжает работать из GitHub Pages до отдельного переноса публикации.
Импорт репозитория не публикует новую версию сайта и не меняет DNS.

Сайт, backend, генератор и общие схемы пока остаются в одном репозитории. Это
позволяет проверять согласованное изменение контракта одним предложением
изменений. Разделение на несколько связанных репозиториев рассматривается после
появления границ сборки и выпуска, которым действительно нужны независимые
истории и права доступа.

## Подготовленная конфигурация

| Файл | Назначение |
| --- | --- |
| `.sourcecraft/ci.yaml` | Сборка сайта и полная проба контрактов для каждого предложения в `master` и после изменения `master` |
| `.sourcecraft/ci/` | Закреплённая среда пробы: Node 24.19.0, Python 3.14.7 и uv 0.12.11 |
| `.sourcecraft/branches.yaml` | Запрет прямого push, force push и удаления основной ветки |
| `.sourcecraft/review.yaml` | Одно явное одобрение текущей итерации; автор может одобрить собственное изменение; режим «Доверять» выключен |

Проверка сайта выполняет `npm ci` и `npm run build`. Проверка контрактов запускает
`docs/research/2026-09-15-message-schemas-probe/run-all.sh` целиком. У CI нет
секретов публикации, доступа к рабочей базе, клиентским файлам или провайдерам
моделей.

Правило ревью не назначает пользователя автоматически: имя учётной записи
SourceCraft нельзя выводить из имени организации. До переключения разработки
владелец проверяет, что только его рабочая роль может одобрять и сливать изменения,
а учётные данные AI-агентов не дают права одобрения, слияния и администрирования.
Если это нельзя выразить ролями проекта, в `review.yaml` добавляется правило с
фактическим именем владельца после первого входа в SourceCraft.

## Порядок выполнения

1. Добавить подготовительный коммит в GitHub `master` до окончательного импорта.
   SourceCraft читает CI, правила ревью и защиту веток из основной ветки, поэтому
   наличие файлов только в `feat/tattoo-generator` не запускает настройку.
2. Остановить новые push и слияния в GitHub. Сохранить полный список
   `refs/heads/*` и `refs/tags/*`, исходные идентификаторы коммитов и экспорт
   переносимых предложений изменений, задач и комментариев.
3. Выполнить один импорт в приватный проект `Rated`: вся Git-история, все ветки и
   теги, предложения изменений, задачи, ревью и комментарии. Постоянное зеркало
   не включать.
4. Сверить ветки, теги и коммиты с исходным снимком. Отдельно перечислить
   обсуждения и вложения, которые SourceCraft не перенёс.
5. Создать тестовое предложение изменений в `master` и дождаться двух зелёных
   задач `quality`: `site-build` и `contract-probe`. Первый запуск выполняется
   без заранее подготовленного кеша. После слияния проверить такой же запуск на
   новом коммите `master`; сам импорт не считается событием `push` без
   наблюдаемого запуска.
6. В отдельной тестовой ветке проверить отрицательные сценарии:
   ошибка сборки и ошибка контракта дают красный статус; обычное слияние без
   зелёных проверок и одобрения невозможно; новый коммит требует новых проверок.
7. Проверить рабочими, неадминистративными учётными данными запрет прямого push,
   force push и удаления временной защищённой ветки с теми же правилами.
8. После приёмки заменить `origin` в рабочих копиях на SourceCraft. GitHub
   сохранить как источник прежней публикации и истории; новые ветки, обсуждения
   и слияния вести в SourceCraft.

## Условия переключения

Переезд разработки принят только при одновременном выполнении условий:

- история, ветки и теги сверены с исходным снимком;
- репозиторий приватный и входит в проект `Rated`;
- обе проверки проходят на точном коммите, который сливается;
- красная, отменённая или отсутствующая проверка блокирует обычное слияние;
- одобрение относится к текущей итерации предложения;
- рабочие учётные данные не обходят защиту основной ветки;
- AI-агент может создать ветку и предложение, прочитать изменения и логи, но не
  может одобрить, слить или изменить настройки репозитория;
- GitHub Pages продолжает отдавать прежнюю опубликованную версию сайта.

Публикация в Yandex Cloud, переключение домена и окончательный статус GitHub —
следующий самостоятельный этап.
